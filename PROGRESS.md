## Phase 1: Rules engine and text check - done

- `lib/rules/taxonomy.ts`: the 14 flags with severity, a short label (for family alerts) and a plain-language reason.
- `lib/rules/rules.ts`: `runRules(text)` returns flags with a quote of at most 12 words (the sentence around the match).
  - Requests in a negated clause are skipped ("we will never ask for your PIN", "never share this code"),
    so a message that delivers a code is not treated as asking for one. The clause stops at commas, so
    "Don't tell anyone, just send me the code" is still caught.
  - `impersonates_bank_or_company` only fires when the message is about a problem or action
    ("unusual activity", "could not be delivered"), not "your statement is ready".
  - No real company or product names appear in the patterns (remote-access tools, gift card brands and
    link shorteners are detected generically; the AI covers named ones in Phase 2).
- `lib/rules/extract.ts`: links (full, www, bare domains on a fixed TLD list; shortened and lookalike heuristics)
  and phone numbers (8-15 digits, skipping codes, money, dates and reference numbers).
- `lib/verdict/index.ts`: `computeVerdict(ruleFlags, ai | null)` in the order from the brief; `mergeFlags` de-duplicates
  rules and AI flags, high severity first. AI `other` flags count as medium. `lib/verdict/copy.ts` holds the words.
- `lib/check/index.ts`: `buildCheckResult` / `checkWithRulesOnly` produce what the result screen needs.
- Parent screens: `/p` (home), `/p/check` (three tiles), `/p/check/text` (type or paste, with a Paste button),
  result screen, `/p/rules` (Golden Rules). Photo and voice tiles go to placeholders.
  - Parent layout sets a 22px base from the first paint; `html.parent-text-xl` gives 28px when the family picks
    Extra Large (`lib/parent/settings.ts`, written in Phase 4).
  - Result: banner with icon and word, up to three reasons with quotes, "What to do now", non-clickable numbers and
    links from the message, "Check something else", and "I think this is wrong".
    Because no AI runs yet, every result shows "We could only do a quick check this time" and the Golden Rules.
  - Focus moves to the verdict heading so screen readers announce it.
- 78 unit tests (rules per flag with positives and negatives, extraction, verdict cases from the brief).
- Checked in the browser: scam sample gives WARNING, the genuine login-code message gives no flags (NOT SURE without AI),
  keyboard submit works, no horizontal scroll at 375px, no console errors.
- `npm run typecheck` now runs `next typegen` first so route types exist on a clean checkout.

## Phase 2: AI analysis - done

- Models (checked against OpenAI docs, Nov 2026): `OPENAI_MODEL=gpt-6.1-terra` (fast, vision, Structured Outputs)
  with `OPENAI_REASONING_EFFORT=none` for speed; `OPENAI_TRANSCRIBE_MODEL=gpt-transcribe` for Phase 3
  (`whisper-1` and the `gpt-4o-*-transcribe` models shut down on Feb 26, 2027).
- Netlify docs now list a 60-second synchronous function limit; the AI call has a hard 8-second timeout.
- `lib/ai/schema.ts`: strict JSON schema (all fields required, no extra properties; flag ids, sender type and
  assessment are enums). `parseAiAnalysis` re-validates everything: drops unknown/duplicate flags, cuts evidence
  to 12 words and the explanation to 3 sentences, clamps confidence, and strips phone numbers and links from the
  AI's own words so the parent is never pointed at a number from the message. Extra field `claimed_person`
  (for example "son") lets the next step call the right family member.
- `lib/ai/prompt.ts`: system prompt with the taxonomy and the "delivers a code is not asking for a code" rule.
  The item goes between markers with a fresh random id; fake markers inside the item are removed.
- `lib/ai/openai.ts` (server-only): raw `fetch` to the Responses API, `store: false`, strict `text.format`.
  Returns a reason on failure (not_configured, timeout, http_error, refused, invalid_output, network).
  Logs only the HTTP status or error name, never content.
- `app/api/check/route.ts`: validates input (`lib/check/request.ts`: text up to 5000 chars, or a JPEG/PNG/WEBP data
  URL up to ~3 MB) and returns only `{ aiStatus, ai }`. Image input works on the server already; the client side
  comes in Phase 3.
- The rules engine and the verdict run on the device (`lib/check/client.ts`), so if the call fails or the phone is
  offline, the parent still gets the rules-only result plus the Golden Rules.
- `lib/check/index.ts`: one pipeline for device, demo and eval. The AI's explanation is shown only when it agrees
  with the verdict, so the words never contradict the banner (for example after a prompt injection).
  AI-found numbers and links are merged with the rules' ones. When the AI is unavailable, `guessSenderType`
  (rules) picks the sender type.
- `lib/next-step`: bank -> saved bank contact; family claim -> that family member (whole-word match on name or
  relationship, so "grandson" does not match "son"); otherwise -> main family member. Rendered as a big `tel:` button.
- `lib/parent/circle-cache.ts`: the circle is read from localStorage (written in Phase 4) so call buttons work offline.
- 112 unit tests. New: schema strictness, parsing and sanitising, marker handling, request validation, the OpenAI
  client with a mocked fetch (store: false, refusal, timeout, no content in logs), next-step choices, and
  injection end-to-end (AI fooled into "likely_normal" at confidence 1 -> still WARNING, explanation hidden).
- Checked in the browser without an API key: the fallback works, the verified bank button is `tel:08081570000`,
  the message's number shows as plain text, bad requests get 400, and the server log has no message content.

## Phase 3: Image and voice - done

- Photo (`/p/check/photo`, `components/parent/PhotoCheck.tsx`): "Take a photo" (camera) or "Choose a screenshot",
  a preview ("Is this the right picture?"), then the check. `lib/image/compress.ts` shrinks to 1600px on the longest
  side and re-encodes as JPEG 0.8 through a canvas, which removes EXIF data such as location (verified in the browser:
  a 3000x2000 PNG became a 1600x1067 JPEG of 54 KB with no EXIF). Photos are turned the right way up first.
  The picture is held in memory only. The result screen shows "What we read in the picture" (collapsed), or
  "We could not read the picture this time" when the AI is unavailable.
- Voice (`/p/check/voice`, `components/parent/VoiceCheck.tsx`): "Start talking" -> recording with a seconds-left
  counter and a big "I have finished" button (auto-stops at 60s) -> "Writing down what you said..." -> check.
  The result shows "You said: ...". Clear messages for no microphone support, microphone refused, transcription
  failed, and silence, each with "Try again" and "Type it instead". The microphone is released on stop or leaving.
- `/api/transcribe` (`lib/ai/transcribe.ts`): multipart upload to `/v1/audio/transcriptions` with `gpt-transcribe`
  and a short context prompt; 20s timeout; webm/mp4/m4a/mp3/wav only, up to 5 MB; audio not stored or logged.
- Read-aloud (`lib/speech`): `speechScript` builds the spoken text in code from the result (verdict as a word,
  explanation, reasons, what to do, the verified button's label) and never reads numbers or links from the message.
  `speak` uses the browser voice at rate 0.9, one sentence at a time (some browsers cut off long speech).
  The result is read automatically and there is a "Read it to me" / "Stop reading" button.
- Rules found a gap in the browser: spoken descriptions use reported speech. The rules now also catch
  "he said not to tell my daughter", "keep it secret", "asked for my PIN", "wanted me to read out the code",
  "asked me for my card number".
- 131 unit tests. New: image sizing, audio formats, transcription client (mocked fetch, nothing logged),
  read-aloud script, reported-speech rules.
- Checked in the browser (no API key): photo compression and fallback, voice states with a synthetic audio stream
  (not the real microphone), "You said" result with a stubbed transcript, auto read-aloud starting.

## Phase 4: Family circle - done

- `supabase/migrations/0001_family_circle.sql`: circles, family_members, contacts, devices, pairing_codes, alerts,
  rate_limits. RLS on with no policies (server-only access). Atomic SQL functions: `create_circle`,
  `replace_circle_settings`, `consume_pairing_code` (once, before expiry), `hit_rate_limit`, `delete_expired`.
  Execute is revoked from `anon`/`authenticated` and granted to `service_role`. Check constraints cap alert summary
  at 200 and excerpt at 500 characters. `supabase/migration.test.ts` runs the migration in PGlite (real Postgres)
  and tests every function.
- Store layer `lib/server/store`: one interface, `SupabaseStore` (supabase-js, service role) and `MemoryStore`
  (tests; also used by `npm run dev` when `SUPABASE_URL` is not set; production refuses to run without Supabase).
- Security (`lib/server`):
  - PIN: scrypt with a random salt. Five wrong PINs lock the circle for 15 minutes (sign-in, settings changes and
    disconnecting a phone all count). Weak PINs (123456, 000000...) are refused.
  - Family session: HMAC-signed httpOnly SameSite=Lax cookie (30 days); state-changing family requests also reject
    other origins.
  - Family sign-in on another device: 8-character family code (no look-alike letters) plus the PIN.
  - Pairing: one-time 6-digit code, keyed hash (HMAC with SESSION_SECRET) in the database, 15-minute expiry, one
    active code per circle, 10 tries per 15 minutes per IP. The phone gets a random 32-byte token; only its SHA-256
    is stored.
  - The parent's phone (Bearer token) can read the circle and create alerts and read replies. It cannot change
    anything, never receives the PIN hash or family code, and loses access when the family disconnects it.
  - Rate limits: `/api/check` and `/api/transcribe` share 30/hour per IP (`RATE_LIMIT_PER_HOUR`); creating circles
    10/hour per IP; sign-in 20/15 min per IP; alerts 20/hour per phone. If the store is down, a per-instance counter
    is used so the AI key stays protected and the demo keeps working.
  - Alerts store only the summary, a 500-character excerpt and flag ids. Never images. Deleted after 7 days
    (removed on every inbox read, plus `delete_expired()` for pg_cron).
- Family screens (`/f`): start, create circle (`CircleForm`: parent name, text size, emergency number, family
  members, verified contacts, PIN), sign in, home (inbox polled every 10 s with one-tap and custom replies,
  "Connect Amina's phone" with code + QR), settings (PIN needed every save, optional new PIN, connected phones
  with PIN-protected disconnect).
- Parent screens: `/p/pair` (6-digit code, or prefilled from the QR link), home shows "Hello Amina" and a call
  button per family member, "Connect to your family" when not paired; the circle refreshes on home and is cached for
  offline use; text size (Large/Extra large) and emergency number come from the circle. The result screen has
  "Show Sara" (explains what is shared), then "Sara will see this. Do not reply to the message while you wait.",
  polling every 5 s; the reply is shown large and read aloud, with a call button.
- `FamilyChannel` (`lib/circle/channel.ts`) abstracts sending and polling, so the demo can use in-browser state.
- Next.js note: route handlers are wrapped with `handle()`, which calls `unstable_rethrow` so the Cache Components
  prerender bail-out on request headers is not swallowed.
- 165 unit tests. New: migration in PGlite, PIN hashing and lockout, session signing and tampering, validation,
  alert building, and the whole loop through the real route handlers (create, pair, alert, reply, poll), plus:
  phone cannot edit contacts, settings need the PIN, lockout after 5, pairing code works once, new code replaces old,
  pairing rate limit, disconnect, cross-site request blocked, circles isolated, 7-day expiry.
- Checked in the browser with the in-memory store: created a circle, made a code and QR, paired via the QR link,
  home showed "Call Sara", a scam check offered "Call Gulf Example Bank" and "Show Sara", the alert appeared in the
  family inbox, the one-tap reply reached the parent's screen; a settings change needed the PIN ("4 tries left" on a
  wrong one) and switched the parent's phone to 28px text.
